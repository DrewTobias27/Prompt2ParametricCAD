# Demo script

This is a short walkthrough for presenting Prompt2ParametricCAD in a portfolio,
interview, or project review.

## One-sentence pitch

Prompt2ParametricCAD converts natural-language or manually selected design
features into validated parametric CAD operation JSON, builds the part with
CadQuery, exports a STEP file, and tracks feature/reference data for future
editable CAD workflows.

## What to have ready

Before the demo:

```powershell
.\scripts\check_setup.ps1
```

Start the web app:

```powershell
.\scripts\run_web_app.ps1
```

Open:

```text
http://127.0.0.1:8000/
```

Optional but useful: have a STEP viewer or CAD program ready so the downloaded
model can be opened immediately.

## Two-minute demo flow

### 1. Open with the problem

Say:

> CAD modeling usually requires manual feature creation. This project explores
> whether simple parts can be generated from structured intent: either a natural
> language prompt or a guided manual builder.

Point out that the system does not just return a mesh or image. It creates a
structured operation list that can be validated, tested, and interpreted.

### 2. Show prompt-based generation

Use this prompt:

```text
Create a 100 mm by 60 mm by 8 mm rectangular mounting plate with four 8 mm circular through holes near the corners and a centered 20 mm by 15 mm rectangular boss on the top face.
```

Click **Generate CAD**.

Show:

- status message
- STEP download link
- generated JSON
- copy JSON button

Say:

> The language model output is constrained to a JSON schema. That makes the
> result inspectable and testable instead of being a black-box CAD command.

If the model succeeds, download the STEP file and open it. If the model fails,
use that as a useful explanation:

> Invalid geometry is expected sometimes, so the project includes validation and
> evals to identify where generation breaks.

### 3. Show manual-builder generation

Switch to **Manual Builder**.

Use a simple reliable configuration:

- Main frame: rectangle
- Turn off reasonable dimensions
- Width: `100`
- Height: `60`
- Thickness: `8`
- Add Feature
- Operation: Cut
- Target face: Base top
- Shape: Circle
- Turn off reasonable dimensions
- Position X: `35`
- Position Y: `20`
- Pattern: Single
- Mirror across X axis: checked
- Mirror across Y axis: checked
- Cut depth type: Through cut
- Diameter: `8`

Click **Build Manual Model**.

Say:

> The manual builder creates the same kind of operation JSON, but with controls
> instead of a prompt. This helps users create more predictable models and gives
> the prompt system a clearer target format.

### 4. Show the technical backbone

Open or mention:

- `src/prompt2cad/schema.py`
- `src/prompt2cad/interpreter.py`
- `src/prompt2cad/feature_graph.py`
- `src/prompt2cad/evaluator.py`
- `evals/cases/rigorous_plate_holes_boss.json`

Say:

> The key design choice is the intermediate CAD JSON. It lets the project split
> natural-language understanding from geometry construction. The same model can
> be generated by the API, built manually, tested with evals, exported as STEP,
> and represented as a feature graph.

### 5. Run evals if there is time

```powershell
$env:PYTHONPATH = "src"
python -m prompt2cad.eval_runner --models-dir generated\evals --cases-dir evals\cases
```

Say:

> The evals check both the operation sequence and the resulting geometry:
> operation counts, dimensions, repeated cuts, solid validity, volume, bounding
> boxes, and feature-graph references.

## Longer five-minute version

If there is more time, add these points:

1. Open `docs/architecture.md` and show the pipeline diagram.
2. Show `docs/setup.md` to demonstrate reproducibility.
3. Export a feature-tree debug JSON:

   ```powershell
   $env:PYTHONPATH = "src"
   python -m prompt2cad.feature_tree_export examples/api_rectangular_plate.json --output generated/api_rectangular_plate_feature_tree.json
   ```

4. Explain the longer-term SolidWorks direction:

   > STEP export gives geometry, but not a true editable feature tree. The
   > feature graph is being built as the intermediate representation needed for
   > future editable export.

## Strong technical points to emphasize

- Uses structured output instead of freeform model text
- Separates intent generation from geometry construction
- Validates generated JSON before building CAD
- Uses CadQuery for real solid modeling and STEP export
- Tracks feature graph data for build order and parent/child relationships
- Supports deterministic fixture-backed evals to avoid relying on API calls for
  every regression test
- Has a manual builder that reduces prompt ambiguity

## Known limitations to mention honestly

- It is a prototype, not a full CAD replacement.
- Complex face targeting is still under development, especially curved surfaces
  and corner-adjacent features.
- STEP export preserves geometry but not a native editable SolidWorks feature
  tree.
- The prompt model can still generate invalid geometry for ambiguous requests.
- The next major direction is strengthening the feature graph and reference
  system so generated models can become more editable.

## Good closing line

> The goal is not just to make a shape once. The goal is to create a clean
> representation of the design intent so the model can be validated, edited,
> regenerated, and eventually exported with more of its feature history intact.
